# Firebase 설정 · 안전한 전환 안내

대상: 기존 `my-daily-tasks-64a0b` 프로젝트와 `jiheeyeom.github.io/my-daily-tasks/` GitHub Pages.

**아래 작업은 소유자의 Firebase 콘솔 권한이 필요합니다. 이 코드만 업로드해도 보안 규칙이 적용되지는 않습니다.** 운영 데이터·현재 규칙은 이 작업에서 읽거나 수정하지 않았습니다.

## 1. 기존 상태 보관

1. 현재 GitHub 버전(이번 변경 전 커밋)을 기록하세요.
2. Firebase Console → Firestore Database → Rules의 기존 규칙을 별도로 보관하세요.
3. 중요한 할 일은 먼저 안전한 위치에 백업하세요. 새 화면에서도 원본을 읽기 전용으로 내려받을 수 있으나, 본격 전환 전 별도 백업을 권장합니다.
4. 전환 중에는 다른 브라우저·기기에서 기존 앱의 입력을 잠시 멈추세요. 새 규칙이 게시되면 이전 무로그인 화면의 접근은 막힙니다. 원본 데이터는 삭제되지 않습니다.

백업은 개인 기기에 보관하고 공개 GitHub에 업로드하지 마세요. 데이터베이스 전체 공개 같은 임시 규칙은 사용하지 않습니다.

## 2. Google 로그인 켜기

1. [Firebase Console](https://console.firebase.google.com/)에서 기존 프로젝트를 엽니다.
2. Authentication → Sign-in method → Google을 사용 설정하고, 프로젝트 지원 이메일을 지정합니다.
3. Authentication → Settings → Authorized domains에 `jiheeyeom.github.io`를 추가합니다. `/my-daily-tasks` 경로는 넣지 않습니다.
4. 로컬 테스트를 할 경우 사용할 호스트(`localhost` 또는 `127.0.0.1`)도 필요에 따라 승인합니다. 기본 등록 여부는 프로젝트 생성 시점에 따라 다르므로 확인하세요.

[공식 Google 로그인 안내](https://firebase.google.com/docs/auth/web/google-signin)

## 3. 내 Firebase UID 확인

1. `js/config.js`의 `securityRulesConfigured: false`를 유지한 버전을 GitHub Pages에 배포합니다. 이 단계에서는 업무와 건강 화면 대신 로그인·설정 안내만 보이는 것이 정상입니다.
2. 내 Google 계정으로 로그인합니다.
3. 화면 아래 ‘계정·설정’의 UID를 복사합니다. Firebase Console → Authentication → Users에서도 확인할 수 있습니다.

UID는 비밀번호가 아니지만, **본인 계정인지 이메일까지 확인**해 주세요. 공유 프로젝트에서 첫 로그인 사용자를 자동으로 소유자로 정하지 않습니다.

## 4. 서버 보안 규칙 적용

기존 할 일을 가져올 경우:

- `firestore.rules`의 `legacyOwner()` 안 `let uid = '';`에 확인한 UID를 넣습니다.
- `js/config.js`의 `legacyOwnerUid: ""`에도 동일한 UID를 넣습니다.

기존 기록 복사가 필요하지 않으면 두 값 모두 빈 문자열로 둡니다. 이때 `my_tasks`는 모든 웹 사용자에게 차단되지만 원본은 데이터베이스에 남습니다.

Firebase Console → Firestore Database → Rules에서 **이 저장소의 `firestore.rules` 전체**를 붙여 넣고 게시합니다. `allow read, write: if true` 같은 기존 광범위 허용 규칙이 남아 있으면 안 됩니다. Firestore의 여러 규칙은 OR로 적용되므로, 보호 규칙을 추가만 하는 것으로는 충분하지 않습니다.

이 파일은 다른 미지의 컬렉션은 기본 거부합니다. 같은 Firebase 프로젝트를 다른 앱도 사용 중이라면 먼저 영향 범위를 확인하고 그 앱의 규칙을 안전하게 병합하세요. 기존 규칙을 모르는 상태에서 다른 앱까지 덮어쓰면 안 됩니다.

콘솔 Rules Playground 또는 소유자가 준비한 테스트 계정으로 다음을 확인하세요:

| 요청                                        | 기대 결과 |
| ------------------------------------------- | --------- |
| 비로그인 → `users/내UID/meals/기록ID`       | 거부      |
| 다른 계정 → `users/내UID/meals/기록ID`      | 거부      |
| 내 계정 → 내 UID 하위 올바른 형식 기록      | 허용      |
| 다른 계정 → `my_tasks/기존ID`               | 거부      |
| 지정한 소유자 → `my_tasks/기존ID` 읽기      | 허용      |
| 소유자 포함 누구든 → `my_tasks/기존ID` 쓰기 | 거부      |

이 규칙은 로그인한 사용자마다 자신의 빈 공간을 사용할 수 있도록 합니다. 다른 사람은 본인 기록을 볼 수 없지만, 사이트 자체를 단 한 계정만 사용하도록 제한하는 UID 허용목록 방식은 아닙니다. 가입 자체도 제한하고 싶다면 별도의 소유자 허용목록 규칙을 적용하세요.

[공식 Firestore 규칙 안내](https://firebase.google.com/docs/firestore/security/get-started)

## 5. 기록 기능 열기

서버 규칙 게시와 권한 확인을 마친 뒤에만 `js/config.js`를 다음과 같이 바꿉니다:

```js
export const appConfig = {
  securityRulesConfigured: true,
  legacyOwnerUid: "확인한-내-Firebase-UID",
};
```

변경 파일을 같은 GitHub Pages에 배포하고 새로고침하세요. **이 플래그는 설정 중 실수를 줄이는 장치일 뿐 보안 장치가 아닙니다.** 실제 보호는 게시된 Firestore 규칙이 담당합니다.

기존 Pages가 `main` 브랜치의 `/ (root)` 배포라면 다음 공개 파일을 포함하면 됩니다:

- `index.html`, `styles.css`, `.nojekyll`
- `js/` 폴더 전체
- `docs/` 폴더 전체

프로젝트 소스 전체를 Git에 반영해도 되지만, `node_modules`, 개인 데이터·백업·키 파일은 절대 올리지 마세요. Firebase 설정 값 중 웹 `apiKey`, projectId 등은 프로젝트 식별용 공개 정보이며, 서비스 계정 키나 AI 비밀키와 다릅니다. 권한은 규칙으로 보호해야 합니다. [공식 설명](https://firebase.google.com/docs/projects/api-keys)

## 6. 이전 할 일 가져오기

1. 지정한 소유자 계정으로 로그인합니다.
2. ‘계정·설정 / 기존 할 일 가져오기’ → ‘기존 할 일 확인’을 누릅니다.
3. ‘원본 백업 다운로드’를 누르고, 내려받은 JSON 파일이 정상적으로 열리고 항목 수가 맞는지 확인합니다.
4. ‘백업 후 내 계정으로 복사’를 누릅니다.
5. 업무 목록에서 내용·완료 상태·BOM/변경/LATER·마감일이 유지되는지 확인합니다.

복사는 `my_tasks/{원본ID}` → `users/{내UID}/tasks/legacy_{원본ID}`로 진행됩니다. 이미 목적지에 존재하면 건너뛰므로 **반복 실행해도 수정된 할 일을 덮어쓰지 않습니다.** 중간 네트워크 오류가 나면 이미 복사한 항목은 남고, 다시 실행하면 나머지를 이어갈 수 있습니다.

빈 내용이나 너무 긴 내용은 건너뜁니다. 알 수 없는 분류는 ‘변경’, 잘못된 마감일은 빈 날짜로 정규화합니다. 원본 전체가 백업에 들어 있으므로 건너뛴 항목은 백업을 보고 수동으로 확인하세요. 이 기능은 어떤 원본도 삭제하지 않습니다.

개인 공간에서 삭제한 가져오기 항목을 다시 복사하면 원본에서 복원됩니다. 따라서 복사 완료 후에는 `legacyOwnerUid`와 규칙의 legacy UID를 다시 빈 값으로 바꿔 이전 컬렉션 접근을 닫아 두는 편이 좋습니다.

## 7. 최종 확인

- 내 음식 한 개 등록 → 식사 기록 → 양 수정 → 새로고침 후 유지 확인.
- 수요일·금요일 기본 운동을 완료 체크하고 기록·시간 수정 확인.
- 체중 입력 → 새로고침 → 같은 날짜 재입력 시 중복 없이 수정되는지 확인.
- 로그아웃하면 개인 화면과 입력 내용이 사라지는지 확인.
- 다른 계정에서 내 업무·건강 기록이 보이지 않는지 확인.
- Safari/Chrome 모바일에서 로그인 팝업, 날짜 입력, 화면 폭 확인.

로컬 계산·DOM·규칙 에뮬레이터 테스트는 포함되지만, 이 실제 계정·배포 검증은 소유자 설정 이후에만 가능합니다.

## 문제 해결

- `auth/operation-not-allowed`: Google 공급자가 활성화되지 않았습니다.
- `auth/unauthorized-domain`: 현재 호스트를 승인 도메인에 등록하세요.
- 팝업 차단/앱 내 브라우저: 팝업을 허용하거나 Safari/Chrome에서 직접 열어 주세요. 자동 로그인 팝업은 띄우지 않고 로그인 버튼 클릭 시에만 요청합니다.
- `permission-denied`: 현재 UID, 서버에 게시된 규칙, 소유자 UID 값을 확인하세요. 권한 오류 후에는 로그아웃·재로그인하여 구독을 다시 시작합니다.
- 빈 업무 목록: 새 개인 공간은 비어 있습니다. 기존 컬렉션이 삭제된 것이 아니며 위의 복사 절차가 필요합니다.
- 저장 중 연결 끊김: 서버 확인 전에는 완료 메시지가 나오지 않습니다. 같은 항목을 여러 번 다시 추가하지 말고 연결 회복·저장 상태를 먼저 확인하세요.
- Firebase 사용량: 이 버전은 사진·AI·Storage·Cloud Functions를 사용하지 않습니다. 실시간 구독은 업무·내 음식 전체와 선택 날짜까지 7일간의 건강 기록을 읽습니다. Firebase 콘솔에서 사용량을 확인하세요.

## 되돌리기

코드는 Git의 이전 버전으로 되돌릴 수 있습니다. 그러나 이전 앱은 로그인 없이 `my_tasks`에 접근하므로 새 보안 규칙 아래에서는 동작하지 않을 수 있습니다. **동작 복구를 위해 건강 데이터가 들어 있는 데이터베이스 전체를 공개하지 마세요.** 새 UI의 설정 플래그를 `false`로 돌려 진입을 일시 중지하고 안전한 규칙은 유지한 상태에서 문제를 해결하세요. 원본 `my_tasks`와 개인 공간의 복사본은 독립적으로 남습니다.
